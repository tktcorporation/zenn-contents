# 何が起きたか

context7 の MCP (Model Context Protocol) を使ってライブラリのドキュメントを取得しようとしたら、「document not found」エラーが出て詰まった話。

React とか mise のドキュメントを引っ張ってこようとしても、全然取れなくて「なんじゃこりゃ！」となった…

# とりあえず解決策

## 動かなかった設定 ❌

最初はこんな感じで設定してた：

```json
{
  "mcpServers": {
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp"
    }
  }
}
```

これだとドキュメント取得がことごとく失敗する。

## 動いた設定 ✅

stdio 使って experimental-fetch オプションを追加したらうまくいった：

```json
{
  "mcpServers": {
    "context7": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "-y",
        "--node-options=--experimental-fetch",
        "@upstash/context7-mcp@latest"
      ]
    }
  }
}
```

# なんでこうなるの？

どうやら http タイプで接続すると、ドキュメント取得のリクエストがうまく処理されないっぽい。  
stdio タイプに変えて、Node.js の experimental-fetch オプションを有効にすることで、正常にドキュメントを取得できるようになる。

GitHub の issue でも同じような報告があがってた：  
https://github.com/upstash/context7/issues/246

# 使い方のポイント

設定変更後は、普通に context7 の機能が使えるようになる：

- React のドキュメント取得 → OK
- mise のドキュメント取得 → OK
- その他のライブラリも問題なし

Claude Code とかで MCP 使う場合は、この設定にしとくと幸せになれるかも。

# まとめ

- context7 MCP で「document not found」エラーが出たら設定を見直そう
- http タイプではなく stdio タイプを使う
- experimental-fetch オプションを忘れずに
- 困ったら GitHub の issue も確認してみると良いかも

同じエラーで詰まってる人の参考になれば！
