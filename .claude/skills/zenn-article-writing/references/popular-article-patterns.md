## タイトルパターン

| パターン | 例 |

| 「〇〇を作った」 | 横断的にパッケージ管理できるツール「lazypkg」を作った |

## 冒頭のフックパターン

1. **個人的な課題起点:** 「〜していると、こういう状況になりがち」
2. **ストーリー/きっかけ:** 「〜に触発されて」「〜がきっかけで」
3. **プロダクト直球:** 1行でツール説明 + リポジトリリンク
4. **自虐型:** 「普段コード書かない奴が」

## ビジュアル要素

- **GIF デモ:** 6記事中5記事で使用。CLI ツール紹介では最重要
- **スクリーンショット:** TUI、GitHub Actions UI 等
- **比較表:** 既存ツールとの機能比較
- **アーキテクチャ図:** Mermaid またはテキストベース

## トーン

- カジュアルな一人称（「作った」「使ってる」「気に入ってる」）
- 限界を正直に認める（「まだ荒削りだけど」「シンプルだが日常的に使っている」）
- 技術的には正確だが、説明は平易に

## クロージング

1. GitHub リポジトリへのリンク + Star/Issue/PR 歓迎
2. 対象ユーザーの明示（「こんな人に使ってほしい」）
3. 今後のロードマップ
4. インストールコマンドの再掲

## 長さ

- ツール紹介系: 1,800〜3,200 語
- 最も包括的な記事で約 3,000 語・11セクション
- 最短で効果的な記事で約 1,800 語・5セクション
